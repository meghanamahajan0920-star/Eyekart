1. EXECUTIVE SUMMARY & ARCHITECTURAL OVERVIEW
--------------------------------------------------------------------------------
The EyeKart database is a normalized relational schema designed for an omnichannel
eyewear and sunglasses e-commerce application. The system supports full product
catalog management with multi-color frame variants, category and brand taxonomies,
shopping wishlist storage, transactional order management with ACID stock controls,
prescription document/power capture, verified customer reviews, and multi-tier
payment tracking (Razorpay Online PG + Cash on Delivery).

Key Architectural Characteristics:
- ACID Transactions: Orders and inventory stock updates are wrapped in MySQL
  transactions with row-level locks ('FOR UPDATE') to prevent overselling.
- Referential Integrity: Cascade deletion rules are enforced on child entities
  (product_variants, order_items, reviews, wishlist, order_prescriptions) while
  customer deletion sets foreign keys to NULL (ON DELETE SET NULL) on historical
  orders to preserve audit and revenue trails.
- Client-Side Cart: Shopping cart persistence is handled client-side via
  browser LocalStorage ('eyekart_cart') for rapid UI interactions; cart data is
  validated and converted into persistent database records ('orders', 'order_items',
  'order_prescriptions') upon successful checkout.

4. APPLICATION-LEVEL RELATIONSHIPS & UNVERIFIED DETAILS
--------------------------------------------------------------------------------
1. `order_items.variant_id` -> `product_variants(id)`:
   - In MySQL, `variant_id` does not have a physical FOREIGN KEY constraint.
   - However, in backend query execution (`server.js`), `variant_id` is passed,
     verified against `product_variants`, and stock is decremented from
     `product_variants` when `variant_id` is supplied.
   - Categorized as: **Application-Level Relationship**.

2. Shopping Cart Storage:
   - There is NO persistent `cart` table in MySQL `eyekart_db`.
   - The shopping cart is managed via React Client-Side Context (`CartContext.tsx`)
     and persisted in the user's browser via `localStorage['eyekart_cart']`.
   - Upon clicking "Place Order" / "Proceed to Payment", the cart array is sent
     directly to `POST /api/orders` to instantiate records in `orders` and `order_items`.

3. Prescription Document Storage:
   - Physical prescription image/PDF files are stored on disk under:
     `backend/uploads/prescriptions/rx_<userId>_<timestamp>_<hex>.<ext>`
   - The database table `order_prescriptions` stores the secure relative URI:
     `/api/prescriptions/file/<safeFilename>`
   - Endpoint `GET /api/prescriptions/file/:filename` enforces JWT ownership checks.

4. External Payment Gateway Integration:
   - Razorpay payment order initiation (`/api/payments/create-order`) and
     signature validation (`/api/payments/verify`) are actively implemented.
   - Razorpay payment IDs (`payment_order_id`, `payment_id`, `payment_signature`)
     are persisted directly in the `orders` table.
